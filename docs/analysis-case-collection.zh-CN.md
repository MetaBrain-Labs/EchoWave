# 分析案例收集与回听学习

[English](./analysis-case-collection.md) | **简体中文**

本期完成分析结果到候选、人工精选或自动入库，再到案例检索与原声回听。复用共享工作区和既有知识入库，不增加 AI 提取任务或账号权限。类别仅用于归类，优点类别本身不是质量认证。

## 使用入口

1. 先创建目标知识库。在分组设置的“知识收集”新增规则，必须指定目标库。默认“自动收集、人工精选”；可以改为“自动直接入库”或“每次手动收集”。
2. 可选择优点、待改进、人工纠正作为案例类别，也可新增或复用稳定标识的自定义类别，修改显示名称。来源可映射优点、待改进、风险、建议、已有自定义标签和人工纠正。
3. 不同筛选字段同时满足，同字段多个值任一满足；空字段不限。关键词匹配理由、建议和关联对话，最低置信度仅限制 AI 来源。
4. 开启规则只接收之后新发布的成功分析和新人工纠正。在规则编辑区保存配置后，可以指定日期、预览匹配数量，再启动历史补收。任务列表展示进度和安全失败原因，失败来源可重试；已有候选、人工编辑及拒绝状态不会因重试改变。
5. 分析标签提供“收集到知识库”和“纠正与补充”；分析概览还可手动选择对话片段。人工纠正保存分类、理由和建议的话术版本，原 AI 判断保持可见。转写正文使用分析任务实际使用的确认版本，修改角色或轮次不会改写原文。
6. 知识库详情的“案例 / 待审核”提供正式案例、候选及审核历史。候选支持编辑、精选、拒绝和批量处理。案例详情分别展示原对话、评价、人工补充及建议，支持顾客、销售及顺序原声回听。

## 持久化、恢复与版本

[迁移 037](../apps/api/migrations/037_analysis_case_collection.sql) 新增规则、人工纠正、案例及版本、媒体、任务和收集批次。成功分析与修正保存通过事务内触发器写入持久事件，冻结当时的规则；Worker 使用 PostgreSQL 租约和 SKIP LOCKED，沿用 LangGraph 命名节点。没有 Redis 队列。

案例是可编辑内容的权威来源，一个正式案例生成一个知识文档检索投影，由既有入库 Worker 向量化并发布 revision。编辑创建新版本，旧 active revision 在新版本成功前继续可检索。通用文档编辑、重命名和替换会要求用户使用案例入口。撤回或删除立即停止检索；知识库或通用文档删除同步删除对应案例并排队清理媒体。既有历史引用继续使用证据快照。

证据保留标签关联片段之间的完整跨度和紧邻之前的顾客轮次。未知角色保持待确认，用户可以调整选中轮次及角色。原音频范围与所保存的确认正文保持对应，建议话术不会被当成原销售回应。

正式音频存放在已有 `KNOWLEDGE_STORAGE_DIR` 的 `case-media` 子目录，使用已有 FFmpeg 配置逐轮生成 MP3。源音频到期清理不影响正式片段。文字检索和媒体生成状态分开显示；源文件缺失、FFmpeg 失败或播放失败不会删掉文字案例，不可用片段不提供播放按钮。恢复来源或修复配置后可重试。案例删除回收全部已记录版本的独立音频；失败清理有最多三次后台尝试。

## 部署与验证

从仓库根目录执行迁移后再启动新版 API：

```sh
pnpm --filter @echowave/api migrate
```

037 依赖前面的编号迁移，包括 036 的文档生命周期。不新增环境变量；独立片段要求知识目录可写及已有 FFmpeg 可运行。备份知识目录时包含 `case-media`。迁移记录与实际结构不一致时，需要先检查并修复迁移历史，不能跳过错误直接启动。

聚焦检查与完整检查：

```sh
pnpm --filter @echowave/contracts test
pnpm --filter @echowave/api test
pnpm --filter @echowave/mobile test -- knowledge-collection collectionApi
pnpm check
```

真实 PostgreSQL 回归需要可访问的 API `.env` 数据库配置和创建 schema 权限。构建 API 后，从根目录运行：

```sh
pnpm --filter @echowave/api build
pnpm --filter @echowave/api exec node test/knowledge/collection/verify-postgres.mjs
```

该脚本在隔离 schema 中执行全部编号迁移，以合成数据验证事件、去重、精选、投影、pgvector 检索、版本、纠正与删除，最终回滚全部 DDL 和数据，不提交业务迁移。普通测试不要求在线数据库。

## 后续边界

正式案例保留真实顾客轮次、销售参考回答、理由、确认版本和独立音频映射。下一阶段可隐藏参考销售回答，播放顾客轮次供学员练习。本期不实现录音、模拟会话或模型评分。

规则文件夹使用新增迁移 `038_collection_rule_folders.sql`。新来源事件冻结规则身份、版本与配置；同一案例可归属多个规则文件夹，但只保留一份独立检索文档。旧自动案例进入“历史收集”，无规则手动案例进入“手动收集”。历史整理只修改同库、同来源分组的归属元数据，不解析文档。目录搜索同时覆盖规则名称和内部案例标题。
